# Задача: улучшение главной страницы LobbyHub

## Контекст

Проект: **LobbyHub**

Сайт: `https://lobbyhub.gg`

LobbyHub — каталог игровых серверов. Пользователь может выбрать игру, найти подходящий сервер, посмотреть его основные параметры и перейти на страницу сервера.

Необходимо доработать существующую главную страницу с точки зрения:

* понятности продукта;
* удобства поиска серверов;
* увеличения количества переходов в каталог;
* SEO;
* внутренней перелинковки;
* дальнейшего масштабирования на новые игры.

Сохрани существующий визуальный стиль сайта. Не требуется полностью переделывать дизайн или создавать новый дизайн-проект.

---

# Цель

После открытия главной страницы пользователь должен сразу понимать:

1. Что представляет собой LobbyHub.
2. Какие игровые серверы здесь можно найти.
3. Как найти сервер для конкретной игры.
4. Почему стоит использовать LobbyHub.
5. Как добавить собственный сервер.

Поисковая система должна однозначно определять, что LobbyHub — это каталог игровых серверов для Rust, Minecraft, Counter-Strike 2, DayZ и других игр.

# Основные требования

## 1. Первый экран

На первом экране должны находиться:

* основной заголовок `H1`;
* краткое описание сервиса;
* поиск;
* основные действия пользователя;
* популярные игры.

### H1

Использовать заголовок:

```text
Find the Best Game Servers
```

Допустим альтернативный вариант:

```text
Discover the Best Multiplayer Game Servers
```

На странице должен быть только один `H1`.

### Подзаголовок

Использовать текст:

```text
Browse multiplayer servers for Rust, Minecraft, Counter-Strike 2, DayZ and more. Compare player counts, locations, ratings and server features.
```

Текст должен отображаться обычным HTML-текстом, а не быть частью изображения.

### Поиск

Поиск должен быть главным элементом первого экрана.

Placeholder:

```text
Search servers by name, game or address
```

Поиск должен позволять искать сервер минимум по:

* названию;
* игре;
* IP-адресу или домену;
* тегам, если они доступны.

При отправке формы пользователь должен переходить на страницу результатов поиска с параметром в URL.

Пример:

```text
/search?q=hypixel
```

Не хранить поисковый запрос только в клиентском состоянии.

### Основные кнопки

Добавить две кнопки:

Primary:

```text
Browse Servers
```

Ведёт в общий каталог или к секции выбора игры.

Secondary:

```text
Add Your Server
```

Ведёт на страницу добавления сервера или авторизации, если добавление доступно только авторизованным пользователям.

Ниже популярных серверов вывести несколько самостоятельных блоков.

* Highest Rated;
* Fastest Growing;

* Featured Servers.

Не дублировать один и тот же сервер многократно на одном экране без необходимости.

# SEO-требования

## Metadata

Для главной страницы установить уникальные метаданные.

### Title

```text
LobbyHub — Find the Best Game Servers
```

Допустимый вариант:

```text
Game Server List for Rust, Minecraft, CS2 and More | LobbyHub
```

Длина title должна оставаться разумной и не должна искусственно включать все игры сайта.

### Description

```text
Discover multiplayer game servers for Rust, Minecraft, Counter-Strike 2, DayZ and more. Compare server activity, locations and features on LobbyHub.
```

### Canonical

```text
https://lobbyhub.gg/
```

Canonical должен формироваться средствами Next.js Metadata API.

---

## Open Graph

Добавить:

* `og:title`;
* `og:description`;
* `og:url`;
* `og:site_name`;
* `og:type`;
* `og:image`.

Для главной страницы:

```text
og:type = website
```

Также добавить Twitter Card:

```text
summary_large_image
```

---

## Индексация

Главная страница должна быть доступна поисковым роботам.

Проверить отсутствие:

```html
<meta name="robots" content="noindex">
```

Проверить, что страница не запрещена в `robots.txt`.

Главная страница должна присутствовать в XML Sitemap.

```text
H1 — Find the Best Game Servers

H2 — Browse Servers by Game
H2 — Popular Game Servers
```

Внутри карточек разрешено использовать `H3`, если это не нарушает структуру компонента.

Не использовать заголовочные теги только ради размера текста.

---

## Внутренняя перелинковка

Главная страница должна содержать обычные HTML-ссылки на:

* общий каталог;
* страницы популярных игр;
* страницы показанных серверов;
* добавление сервера;
* вход или регистрацию;
* информационные страницы в footer.

Ссылки должны иметь понятный текст.

Не использовать в качестве единственного текста ссылки:

```text
Click here
Learn more
More
```

Допустимо использовать `View All Servers`, если контекст секции понятен.

## Структурированные данные

Добавить JSON-LD для `WebSite`.

Пример структуры:

```json
{
  "@context": "https://schema.org",
  "@type": "WebSite",
  "name": "LobbyHub",
  "url": "https://lobbyhub.gg/",
  "potentialAction": {
    "@type": "SearchAction",
    "target": {
      "@type": "EntryPoint",
      "urlTemplate": "https://lobbyhub.gg/search?q={search_term_string}"
    },
    "query-input": "required name=search_term_string"
  }
}
```

Добавлять `SearchAction` только в том случае, если маршрут поиска действительно работает по указанному URL.

Также добавить данные `Organization`, если для сайта доступны:

* официальный логотип;
* юридически или продуктово корректное название;
* официальные социальные сети.

Не добавлять фиктивные рейтинги, отзывы или количество серверов в структурированные данные.

# Требования к Next.js

Использовать актуальные возможности проекта и существующую архитектуру.

Предположительно проект использует Next.js App Router.

## Server Components

Основной контент главной страницы должен рендериться на сервере.

Не превращать всю страницу в Client Component.

Клиентскими должны быть только интерактивные части:

* строка поиска;
* карусель, если она действительно нужна;
* интерактивные фильтры;
* элементы, требующие состояния браузера.

Тексты, заголовки, списки игр и серверов должны присутствовать в первоначальном HTML.

---

## Получение данных

Данные игр и серверов получать через существующий API проекта.

Не создавать mock-данные в production-коде.

Для каждого запроса предусмотреть:

* обработку ошибки;
* пустое состояние;
* таймаут или корректное поведение при недоступности API;
* отсутствие падения всей страницы из-за одной секции.

Если конкретная секция не получила данные, страница должна продолжать работать.

---

## Кэширование

Использовать серверное кэширование Next.js в соответствии с частотой обновления данных.

Ориентировочно:

* список игр — длительное кэширование;
* популярные серверы — 5–15 минут;
* недавно добавленные — 5–15 минут;
* текущий онлайн — более короткий период, если он показывается как актуальный.

Не отключать кэширование всей страницы без необходимости.

Не использовать `force-dynamic`, если страница может работать через ISR или кэшируемые серверные запросы.

---

## Навигация

Все внутренние переходы должны использовать `next/link`.

Не использовать:

```javascript
window.location.href
```

для обычной внутренней навигации.

Не помещать интерактивные элементы внутрь других интерактивных элементов.

Избегать конструкции:

```html
<a>
  <button>...</button>
</a>
```

Использовать один семантически корректный кликабельный элемент.

# UX-требования

## Loading

Не показывать полноэкранный loader при загрузке второстепенных секций.

Использовать skeleton только там, где он действительно нужен.

При серверном рендеринге основной контент не должен мигать или появляться после полной загрузки JavaScript.

## Empty state

Если серверов в секции нет, не показывать пустую сетку.

Допустимые варианты:

* полностью скрыть секцию;
* показать понятное сообщение;
* предложить перейти в каталог.

## Ошибки

Не показывать пользователю технические сообщения API.

Плохой вариант:

```text
Request failed with status code 500
```

Хороший вариант:

```text
Servers are temporarily unavailable.
```

## Адаптивность

Проверить страницу минимум на ширинах:

* 320 px;
* 375 px;
* 768 px;
* 1024 px;
* 1440 px.

На мобильных устройствах:

* поиск должен занимать доступную ширину;
* кнопки не должны выходить за границы;
* карточки не должны иметь горизонтального скролла;
* заголовки не должны обрезаться;
* основные действия должны оставаться видимыми.

---

# Производительность

Не ухудшить Core Web Vitals.

## Изображения

Использовать `next/image`, когда это возможно.

Для каждого изображения указывать:

* размеры или корректный `fill`;
* `sizes`;
* информативный `alt`;
* lazy loading для изображений ниже первого экрана.

Изображение первого экрана, влияющее на LCP, можно загружать с повышенным приоритетом.

Не ставить `priority` всем изображениям.

## JavaScript

Не подключать тяжёлые библиотеки только ради простой карусели или анимации.

Не делать всю главную страницу клиентской.

## Layout Shift

Заранее резервировать пространство под:

* изображения;
* карточки;
* статистику;
* skeleton-компоненты.

---

# Доступность

Необходимо обеспечить:

* доступность всех действий с клавиатуры;
* видимый `focus`;
* корректные `aria-label` у кнопок только с иконкой;
* связанный `label` у поиска;
* достаточный контраст текста;
* корректные `alt` у изображений;
* отсутствие кликабельных `div`, когда можно использовать `a` или `button`.

Поле поиска должно иметь семантическую форму:

```html
<form role="search">
```

```text
HomePage
├── HeroSection
```

```typescript
type ServerSectionProps = {
```

Использовать существующие компоненты проекта, если они уже решают задачу.

Не создавать дубликаты компонентов карточек игр и серверов.

---

# Локализация

Не хардкодить пользовательские тексты непосредственно во множестве компонентов, если в проекте уже используется система локализации.

Если локализация пока отсутствует, сгруппировать тексты так, чтобы их можно было вынести в словари позднее.

Не добавлять переключатель языка в рамках этой задачи, если механизм локализации ещё не реализован.

---

# Что не входит в задачу

В рамках данной задачи не требуется:

* полная смена фирменного стиля;
* разработка новой дизайн-системы;
* создание блога;
* создание страниц игр;
* создание новых API-методов без объективной необходимости;
* реализация сложного алгоритма рекомендаций;
* реализация платного продвижения серверов;
* генерация SEO-текста через AI на каждом запросе;
* добавление фиктивных серверов, рейтингов или статистики.

Если для секции пока нет данных или API, подготовить компонент и подключить только доступные достоверные данные. Не имитировать активность проекта.

# Критерии приёмки

Задача считается выполненной, если:

1. На странице есть один понятный `H1`.
2. На первом экране понятно назначение LobbyHub.
3. Поиск является заметным основным действием.
4. Есть ссылки на страницы популярных игр.
5. Есть минимум одна подборка реальных серверов.
6. Есть CTA для добавления сервера.
7. На странице присутствует видимый SEO-текст.
8. Metadata формируется через Next.js.
9. Установлен canonical главной страницы.
10. Добавлены Open Graph и Twitter metadata.
11. Добавлен валидный JSON-LD `WebSite`.
12. Основной контент доступен в серверном HTML.
13. Страница корректно работает на мобильных устройствах.
14. Отсутствуют ошибки lint, TypeScript и production build.
15. Не появились фиктивные данные.
16. Внутренняя навигация не вызывает ошибку `This page couldn’t load`.
17. Текущий визуальный стиль LobbyHub сохранён.
